Shell quest

Eight things to find, and the only way to look is by typing. Thirteen Unix commands are implemented here — ls, cd, cat, grep, find, chmod, head, tail, wc, file, strings, echo and pwd — over a filesystem that exists only in this page. They are reimplementations, not a shell, and the puzzles get harder as the commands you need get less obvious.

What this is, and what it is not

Thirteen reimplementations, not a shell

Every command here is a few dozen lines of JavaScript walking an object tree. There is no process, no kernel, no job control, and deliberately no pipes, no redirection and no variables, because each of those needs a parser and none of them makes a puzzle better. If you want the real thing — a kernel, a package manager, a shell that can be broken — /labs/linux boots one in the browser.

The answers are read back out of the files

The logs are generated from one fixed seed, and the accepted address in auth.log, the unit that failed at the end of boot.log and the length of the longest line in notes.txt are then computed from that generated text by the same functions your grep and wc call. Writing an answer down next to a 200-line log is how it comes to disagree with the log a year later.

file reads bytes, and names are not evidence

One of the uploads is a PNG called photo.txt and one is plain text called notes.png. file ignores both names and looks at the first few bytes: a PNG starts with 89 50 4E 47, a gzip stream with 1F 8B, an ELF binary with 7F 45 4C 46. That is the whole trick, and it is why an extension is a suggestion rather than a fact.

The permission model is simpler than the real one

Real Unix modes are three sets of three bits for user, group and others, plus setuid, setgid and the sticky bit, and on a directory the execute bit means something different again. chmod here sets all nine bits correctly and ls -l prints them correctly, but only the owner read bit is ever consulted when deciding whether you may read a file, because there is exactly one user and modelling the rest would add explaining without adding a puzzle.

Questions people ask

Is this a real Linux shell?
No. Thirteen commands are reimplemented in JavaScript over a filesystem held in memory. For a real kernel and a real shell, both running in the browser, use the Linux terminal in Labs.
Are there pipes and redirection?
No. No |, no >, no variables and no command substitution. Every quest is solvable with one command at a time, and several are easier that way.
Why does wc -c disagree with a real machine?
Files here are JavaScript strings, so wc counts characters. A real wc counts bytes, and any character outside ASCII is more than one byte. Everything in this filesystem is ASCII, so for these files the two happen to agree.
Is the filesystem the same every time?
Yes. One fixed seed builds it, so the logs, the addresses and the answers are identical on every run and on every device. Restarting resets the permissions you changed.
What counts towards the best score?
Every command you run, including help, hint, clear and wrong answers. Lower is better, and a first pass of around thirty is a reasonable showing.
Does anything I type leave the page?
No. There are no network calls anywhere in this game. The only thing stored is the number of commands your best run took, in this browser.
