Algorithm visualizer

The difference between O(n²) and O(n log n) is a shrug on paper and obvious the moment you watch quicksort lock in a sorted block while bubble sort is still shuffling. Thirteen sorts and six pathfinders, animated, steppable, with the counts ticking.

Seeing complexity

Why watch a sort

Everyone learns that quicksort is faster than bubble sort, and almost nobody feels it until they watch them side by side on the same data. The comparison counts make the asymptotic difference concrete: the same array, an order of magnitude fewer operations.

Pathfinding is even more visual

On a grid, Dijkstra floods outward in every direction while A* leans toward the goal, and both find the same shortest path. Draw a wall between start and end and watch the frontier bend around it — that is the algorithm thinking, made visible.

Made to poke at

Change the array shape (nearly sorted, reversed, few unique) and see which algorithms cope and which fall apart. Draw your own maze. Step one operation at a time, forwards or back, to see exactly what each move does.

Smooth by design

Each run is recorded once and replayed frame by frame, so the animation stays smooth, the speed control is real, and stepping backwards is free — all without blocking the page.

Questions people ask

Which algorithms are included?
Thirteen sorts: quicksort, merge sort, heap sort, shell sort, comb sort, cocktail shaker sort, gnome sort, odd-even sort, insertion sort, selection sort, bubble sort, counting sort and radix sort (LSD). Six pathfinders: breadth-first search, depth-first search, Dijkstra, A*, greedy best-first and bidirectional BFS. There are also side-by-side comparison modes (bubble vs quicksort, Dijkstra vs A*).
Why are counting sort and radix sort so much faster to watch?
Because they are not comparison sorts. Instead of comparing pairs of values they bucket by the value itself, which is why they can beat the O(n log n) barrier - at the cost of only working on integer keys in a known range, which is exactly what the bars here are.
Can I draw my own maze?
Yes. In pathfinding mode, drag on the grid to paint or erase walls, and drag the start and end cells to reposition them. There are also generators for random walls and a perfect maze.
Can I step through one operation at a time?
Yes. Pause, then use the arrow keys to move one operation forward or back - the whole run is recorded, so stepping in either direction is instant.
Is it accurate to the real algorithms?
Yes. Each animation is driven by the real algorithm running on the data and recording its actual comparisons and swaps; the visualisation replays those exact operations.
Does it run on my machine?
Entirely. It is canvas and JavaScript in your browser, with no server and no network call.
