Peer-to-peer chat, and why a browser cannot listen on a port

Two browsers, one direct connection, nothing in between. This is as close as the web gets to netcat — and the ways it cannot get closer are the interesting part.

  • Direct browser-to-browser over WebRTC
  • No server relays your messages
  • No account, no database, nothing stored
  • Watch the ICE handshake as it happens
  • The one lab here that uses the network
This lab is the exception. The other tools in Labs never open a network connection — that is their whole point. This one has to: it connects your browser directly to someone else's. Your messages are not stored anywhere and do not pass through this site, but they do leave your machine, and the person on the other end can read them. Treat it as a demonstration, not as a private messenger.

Why there is no “listen” button

netcat has two halves. One side listens on a port and waits; the other dials that address and port. A browser can only ever do the second. There is no JavaScript API that binds a socket and accepts an incoming connection — not a slow one, not a restricted one, none at all.

That is deliberate. A page that could listen would make every open tab a reachable server. Any site you visited could scan the tabs beside it, or address them directly, and a browser would become an attack surface the moment it was opened. The sandbox closes that door completely, and it is one of the more important doors it closes.

So how do these two find each other?

They cannot, unaided — which is why this lab asks you to carry the first message yourself. Each side writes a description of how it can be reached, and the two of you pass those descriptions between you over some channel you already share. After that the browsers talk directly, and nothing else is involved.

What STUN is doing

On the same wifi this works with nothing outside this page at all — both machines can see each other's local addresses. Across the internet each one is behind a router and does not know its own public address, so it asks a STUN server one question: what address do you see me coming from? That answer goes into the code you paste. No message ever travels through it.

Some networks defeat this entirely. If both sides are behind strict NAT, no pair of addresses works and the only fix is a TURN server that forwards traffic for you — which costs real money to run, so this lab does not have one. When it happens the page says so instead of spinning. Trying it on a different network, or both on the same wifi, usually works.
