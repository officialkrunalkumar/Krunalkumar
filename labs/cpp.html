Online C++ compiler

Real clang with the real libc++, compiled to WebAssembly. That distinction matters: std::vector, std::string, std::map, <algorithm>, templates and lambdas all work, because this is an actual compiler and an actual standard library rather than an interpreter covering a subset. Every part of it runs on your machine.

  • Real clang + libc++
  • ~58 MB once, then cached
  • The whole STL
  • Templates and lambdas

Before you start

This playground runs entirely inside your browser. Please read what it can and cannot do, then choose whether to continue.

What is not supported

  • Installing libraries or packages of any kind
  • Network access from your program
  • Reading or writing files on your computer
  • Long-running, timing-sensitive or benchmark work
  • Anything beyond the standard library

What you get

  • Your code runs on your machine, in your RAM
  • Nothing is uploaded, logged or stored by us
  • No account, no queue, no execution limits
  • Works offline once the runtime is cached
  • Free, permanently

How to compile and run C++ online

  1. Accept the short notice, then write your program in the editor.
  2. For std::cin, put each value on its own line in the Input (stdin) panel before running.
  3. Press Run, or Ctrl + Enter.
  4. The first run fetches the toolchain (~58 MB); after that a compile takes about a second and a half.
  5. Compiler diagnostics and your program’s output share the terminal pane, with the toolchain’s own progress lines dimmed.

What this C++ compiler supports

A real compiler with a real standard library. The limits are the sandbox around it, not gaps in the language.

Works here

  • The STL in full — vector, string, map, set, deque, <algorithm>, <numeric>
  • Classes, inheritance, virtual dispatch, operator overloading and RAII
  • Templates, both function and class, plus lambdas and auto
  • Smart pointers: unique_ptr, shared_ptr, make_unique
  • Exceptions, <sstream> and the iostream family
  • Compiler warnings and errors, with the caret under the offending token
  • Reading from the Input panel with the usual standard-library calls

Does not work here

  • Multiple translation units, your own headers, or third-party libraries such as Boost
  • The newest standards — the sysroot is a C++17-era libc++, so concepts, ranges and coroutines are not available
  • Threads, sockets and file I/O against your own disk
  • Inline x86 assembly — the target is WebAssembly

Vectors, sorting and lambdas

The real libc++, so and lambdas work as written.

#include <iostream>
#include <vector>
#include <algorithm>
#include <numeric>

int main() {
    std::vector<int> marks = {68, 91, 45, 84, 77, 96};

    std::sort(marks.begin(), marks.end(), std::greater<int>());

    for (int m : marks) std::cout << m << " ";
    std::cout << "\n";

    int total = std::accumulate(marks.begin(), marks.end(), 0);
    std::cout << "top     " << marks.front() << "\n";
    std::cout << "average " << total / (double)marks.size() << "\n";
    return 0;
}

Classes and inheritance

Virtual dispatch, constructors and destructors, all genuinely compiled.

#include <iostream>
#include <vector>
#include <memory>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual std::string name() const = 0;
};

class Circle : public Shape {
    double r;
public:
    explicit Circle(double r) : r(r) {}
    double area() const override { return 3.14159265 * r * r; }
    std::string name() const override { return "circle"; }
};

class Rect : public Shape {
    double w, h;
public:
    Rect(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
    std::string name() const override { return "rect"; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(2.0));
    shapes.push_back(std::make_unique<Rect>(3.0, 4.0));

    for (const auto &s : shapes) {
        std::cout << s->name() << " area " << s->area() << "\n";
    }
    return 0;
}

Maps and strings

A word count, the way you would actually write it.

#include <iostream>
#include <map>
#include <string>
#include <sstream>

int main() {
    std::string text = "the quick brown fox jumps over the lazy dog the fox";
    std::map<std::string, int> counts;

    std::istringstream in(text);
    std::string word;
    while (in >> word) counts[word]++;

    for (const auto &pair : counts) {
        if (pair.second > 1)
            std::cout << pair.second << " x " << pair.first << "\n";
    }
    return 0;
}

Templates

A function template and a class template, instantiated at compile time.

#include <iostream>
#include <vector>

template <typename T>
T biggest(const std::vector<T> &items) {
    T best = items.at(0);
    for (const T &i : items) if (i > best) best = i;
    return best;
}

template <typename T>
class Box {
    T value;
public:
    explicit Box(T v) : value(v) {}
    const T &get() const { return value; }
};

int main() {
    std::cout << biggest<int>({3, 9, 2}) << "\n";
    std::cout << biggest<std::string>({"pear", "apple", "fig"}) << "\n";

    Box<double> b(2.5);
    std::cout << b.get() << "\n";
    return 0;
}

Questions people ask

Is this really clang, with the real STL?
Yes. clang and lld are compiled to WebAssembly and linked against a genuine libc++. That is why std::vector, std::map and <algorithm> behave the way they do locally.
Which C++ standard does it support?
The sysroot is a C++17-era libc++. Everyday modern C++ — auto, lambdas, range-for, smart pointers, structured use of the STL — all works. Concepts, ranges and coroutines from C++20 do not.
Why is the first run slow?
clang and lld together are about 58 MB, downloaded once and then cached by your browser. Later compiles take roughly a second and a half.
How do I provide input to cin?
Type the values into the Input panel below the output, one per line, before pressing Run. Each extraction reads the next one.
Can I use Boost, or split across headers?
No — a single source file is compiled, and only the standard library is available. There is no package manager and no network access.
Is my C++ code private?
Entirely. Compilation, linking and execution all happen inside your browser tab. No build server exists, so your code is never transmitted.
