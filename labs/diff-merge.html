Diff and three-way merge

Two files that look identical and will not compare, or a merge you do not trust. This runs a real Myers diff and a real three-way merge here in the tab — and when the only difference is a line ending, it says that in those words instead of painting the whole file red.

  • Myers diff, side by side or unified
  • Word and character highlighting inside a line
  • CR, LF and trailing spaces made visible
  • Conflicts resolved by hand, never guessed
  • A unified patch that actually applies

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No rename detection, no binary files, no submodules
  • Line-oriented, so a reformat reads as a rewrite
  • Each box stops at 20,000 lines and 400,000 characters
  • The edit distance is capped, and it says so when it hits the cap

Why that matters here

  • Unreleased source and private config stay on your machine
  • A patch you export is built here, never fetched
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

A text box cannot hold a carriage return — the browser turns every CRLF you paste into a plain LF. To compare real line endings, open the files with the buttons below, or drag one onto a box.

Report — counts, line endings, and what this could not tell you

        

      


      

        

          
How this compares two pieces of text

        

        

          

            
The invisible difference is usually the answer

            
When a diff reports every line as changed, the text is nearly always the same and something you cannot see is not. A line ending that flipped from LF to CRLF; an editor that trims trailing spaces on save; a final newline that went missing. All three are counted per side on every run, and if two inputs differ only in their line endings the report says that sentence rather than showing you a red file and letting you guess.

          

          

            
Myers, and the ceiling it runs into

            
The diff is the greedy O(ND) algorithm from Myers’ 1986 paper, with the common prefix and suffix trimmed off first and the search trace kept so the edit script can be walked back out of it. Keeping that trace costs memory in proportion to D squared, so D is capped at 1,200. Past the cap the differing middle is reported as one block removed and one block added — correct, coarser than minimal, and said out loud in the report rather than hidden. The linear-space refinement in the same paper would remove the cap; it is not implemented here.

          

          

            
Why three-way beats two-way

            
Compare two files and a missing line is ambiguous: it was either deleted on the left, or it never existed and was added on the right. Those call for opposite merges. A base settles it — whichever side differs from the base is the side that moved. That is the entire argument, and it is why a region changed on one side only applies cleanly here, while a region changed on both sides to different text is handed back to you.

          

          

            
The patch arithmetic, and why the export ignores the toggle

            
A hunk header counts context lines as well as changed ones, writes a count of one without the comma, and takes the line before the range when a side is empty. Get any of that wrong and the patch is worse than no patch. The whitespace toggle deliberately never reaches the export: a patch built from an ignore-whitespace diff copies the wrong side’s indentation into its context lines and then fails to apply.

          

        

      


      

        

          
Questions people ask

        

          

            Why does my diff say every line changed?
            
Almost always line endings. One copy of the file uses CRLF and the other uses LF, so every line differs by a character you cannot see. Paste both sides here: if the text is otherwise identical, the report says so in exactly those words and gives the CRLF and LF counts per side. The other common causes are trailing whitespace and a missing final newline, and both are counted too.

          

          

            Does the whitespace toggle change the exported patch?
            
No, and that is deliberate. The toggle changes what the view shows and the hunk counts it compares. The patch and the merge are always computed with whitespace respected, because a patch generated from an ignore-whitespace diff writes the wrong indentation into its context lines and will not apply. The report repeats this whenever the toggle is not set to respect whitespace.

          

          

            What counts as a conflict?
            
A region of the base changed on both sides, to different text. If only one side changed it, that side wins. If both sides changed it to the same text, that applies cleanly too. Insertions are the awkward case, because they cover no base lines at all: an insertion collides with another edit only when it lands strictly inside that edit’s range, or at exactly the same point as another insertion.

          

          

            Will the patch it exports really apply?
            
That was the point of writing it, and the hunk arithmetic was checked against real git apply while building it — including the awkward cases: an insertion at the top of a file, a deletion of everything, a one-line file, and a missing final newline on either or both sides. It writes ordinary unified diff with three lines of context, so git apply or patch -p1 should take it. The file name in the headers is yours to set.

          

          

            Why does a reformatted file look like a rewrite?
            
Because this is line-oriented, and after a reformat almost no line is the same line any more. Ignoring whitespace helps when only the indentation moved; it cannot help when a formatter rewrapped the text, because then the lines genuinely are different lines. No whitespace mode fixes that, and this one does not pretend to.

          

          

            Is anything uploaded?
            
No. There is no server to upload to. The text is read from the boxes on the page, compared in this tab, and any file you download is built here and handed back through a blob URL. That matters more than usual for this tool, because what people want to diff is very often unreleased source or a config file with credentials in it.
