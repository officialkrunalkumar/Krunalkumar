DNS lookup

A browser has no UDP socket, so it cannot speak DNS the ordinary way. DNS-over-HTTPS is the way in — a genuine lookup that happens to travel over HTTPS. You pick which resolver sees it.

  • A, AAAA, CNAME, MX, TXT, NS, SOA, CAA
  • Your choice of resolver
  • DNSSEC status shown
  • No proxy — direct from your browser
  • Nothing sent until you press the button

This tool uses the network

Most of Labs runs with no server at all. This one is different, and the notice is different to match: using it sends a request to Google Public DNS or Cloudflare, whichever you pick, and they will see it.

What leaves your browser

  • They see the domain you look up and your IP address.
  • Your IP address, as with any request you make
  • Nothing is sent until you press the button
  • One request per lookup, or six for “common records”

What still holds

  • No proxy — the request is not relayed through me
  • I never see it, log it or store it
  • No account, no history, no cookies sent
  • Every request is echoed on screen as it goes out
  • Free, permanently

If you are investigating something sensitive, that matters: Google Public DNS or Cloudflare, whichever you pick learns which domain you looked up and roughly when. Agreeing here does not affect the offline tools, and agreeing to those did not bring you through this notice.

How this works

        

        

          

            
Why DNS-over-HTTPS

            
Ordinary DNS runs over UDP port 53. A browser cannot open a UDP socket at all, so no web page can send a classic DNS query. DoH carries the same queries and answers over an HTTPS request, which a browser can make — so this is a real lookup, not an approximation.

          

          

            
NXDOMAIN is not the same as NODATA

            
NXDOMAIN means the name does not exist. NODATA means it exists but has no record of the type you asked for — a domain with a website but no mail returns NODATA for MX. Tools that collapse both into “not found” hide a meaningful difference.

          

          

            
Who sees your query

            
Whichever resolver you pick, and only that one. This is true of every DNS query you have ever made — your ISP’s resolver sees all of them — the difference is that here you chose. There is no proxy of mine in the path.

          

          

            
The AD flag

            
When set, the resolver cryptographically validated the answer through DNSSEC. Most domains are still unsigned, so an absent flag is ordinary rather than suspicious.

          

        

      


      

        

          
Questions people ask

        

          

            Does this use a proxy or a server of yours?
            
No. Your browser makes the request directly to Google or Cloudflare. Nothing is relayed through me and I never see the query.

          

          

            Why can a web page not do a normal DNS lookup?
            
Because DNS runs over UDP port 53 and browsers have no raw socket access. DNS-over-HTTPS exists precisely to make DNS reachable from environments like this one.

          

          

            Which resolver should I pick?
            
Either works. Cloudflare states it does not log the querying IP to disk and purges logs quickly; Google retains some data. If you have a preference, the picker is there so you can act on it.

          

          

            Is the result cached?
            
The resolver serves from its cache, so a TTL you see may be counting down from a lookup somebody else caused. Values fresh from the authoritative server show the full TTL.

          

          

            Why does the same domain give different answers?
            
Large sites use geographic and load-based routing, so the answer legitimately depends on which resolver asked and from where.
