File type inspector and hex viewer

An extension is a suggestion. The first few bytes of a file are what actually say what it is, and this reads those — along with a hex dump, the printable strings inside, and an entropy graph that shows where the compressed or encrypted parts are.

  • 33+ file signatures
  • Extension mismatch detection
  • Hex dump & printable strings
  • Shannon entropy graph
  • Nothing uploaded

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Large files are capped so the page stays responsive
  • No lookups against any external database

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

Reading a file you do not trust

        

        

          

            
Magic bytes beat extensions

            
Renaming invoice.exe to invoice.pdf changes nothing about the file. The first bytes still read MZ, and this will say so. That mismatch is one of the oldest and still most effective tricks in email-borne malware.

          

          

            
What entropy tells you

            
Shannon entropy measures how unpredictable the bytes are, from 0 to 8 bits per byte. Text sits around 4–5. Compressed and encrypted data sits at 7.9 and above, because both are designed to look random. A block of very high entropy inside an otherwise ordinary file is worth a look.

          

          

            
Strings are where the answers hide

            
Pulling the printable runs out of a binary is the fastest first pass in malware analysis. URLs, file paths, registry keys, error messages and the compiler used all tend to survive in plain text.

          

          

            
Why doing this locally matters

            
The entire point of inspecting a suspicious file is that you do not trust it. Uploading it to a website to find out what it is hands a possibly malicious sample, and possibly your confidential document, to a third party. Here it never leaves the tab.

          

        

      


      

        

          
Questions people ask

        

          

            How does it know the file type?
            
By the magic bytes - a short fixed signature at the start of the file. PDFs start with %PDF, PNGs with a 8-byte sequence ending in PNG, Windows executables with MZ, ZIP-based formats with PK. The tool checks against 33 of these signatures.

          

          

            Can it detect a renamed executable?
            
Yes, and it warns explicitly when the extension disagrees with the signature. That is the single most useful thing this tool does.

          

          

            Is the file uploaded anywhere?
            
No. It is read locally with the FileReader API and analysed in the page. There is no server and no network request, which is what makes it safe to point at something you do not trust.

          

          

            What does high entropy mean?
            
Close to 8 bits per byte means the data is compressed, encrypted or already packed. It is normal for a ZIP or a JPEG. It is more interesting inside a document or an executable, where it can indicate an embedded payload.

          

          

            Will it open the file or run it?
            
No. The bytes are read and analysed as data. Nothing is executed, and no embedded content is rendered.
