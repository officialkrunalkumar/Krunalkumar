Hash generator and verifier

Compute a digest for text or a file, check it against a checksum you were given, or work out what an unknown hash is. Files are read in this tab, so hashing evidence does not mean handing it to somebody.

  • MD5, SHA-1, SHA-256, SHA-384, SHA-512
  • HMAC with any key
  • Verify against an expected value
  • Files up to 512 MB
  • Nothing uploaded

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Large files are capped so the page stays responsive
  • No lookups against any external database

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

What the digests mean

        

        

          

            
Why MD5 and SHA-1 are flagged

            
Both have practical collision attacks: two different files can be made to share a digest. That breaks any claim of the form “this hash proves the file was not tampered with”. They still appear here because older evidence manifests, download pages and forensic reports are full of them, and you need to be able to check those.

          

          

            
Hash versus HMAC

            
A plain hash proves the bytes did not change. It proves nothing about who produced them — anyone can recompute a hash. An HMAC mixes in a secret key, so a matching value also proves the sender held that key. Webhook signatures work this way.

          

          

            
Verifying a download

            
Paste the checksum from the vendor into the expected field and load the file. If they match, the file you have is the file they published. If the vendor only publishes MD5, that check is weaker than it looks — it catches corruption, not a deliberate substitution.

          

          

            
Identifying an unknown hash

            
Length narrows it down but rarely settles it: MD5 and NTLM are both 32 hex characters and nothing inside the value distinguishes them. Formats with a prefix — $2b$ for bcrypt, $argon2id$ — identify themselves, and those are the ones you want to be storing.

          

        

      


      

        

          
Questions people ask

        

          

            Is my file uploaded when I hash it?
            
No. The file is read with the browser FileReader API and hashed in the page. There is no server in this tool, and no request carrying your data is ever made - open the Network tab and you will see nothing leave while you use it. (The page itself loads analytics, like every page on this site; that is a pageview, and it never contains your input.)

          

          

            Which hash should I use?
            
SHA-256 for anything new. It is fast, widely supported and has no known practical attack. Use SHA-512 if you want more margin. Do not use MD5 or SHA-1 for anything that needs to resist a deliberate attack.

          

          

            Can I hash a password with this?
            
You can, but you should not store the result. Passwords need a slow, salted algorithm such as bcrypt, scrypt or Argon2id. A fast hash like SHA-256 is exactly the wrong tool because it lets an attacker try billions of guesses per second.

          

          

            What is the largest file I can hash?
            
The limit here is 512 MB. Above that the browser tab starts to struggle, since the work happens on your processor rather than a server.

          

          

            Does this work offline?
            
Yes. Once the page has loaded it needs no network at all, and it stays in your browser cache, so it works on a disconnected machine.
