JWT decoder and verifier

A JWT is a bearer credential: whoever holds it can act as that user until it expires. Pasting a production token into a website hands that credential to whoever runs the site. This one has no server behind it — check the Network tab and see for yourself.

  • Header, payload and claims explained
  • Expiry and not-before checks
  • HMAC signature verification
  • Warns on alg: none
  • Token never transmitted

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Large files are capped so the page stays responsive
  • No lookups against any external database

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

What a JWT actually guarantees

        

        

          

            
Decoding is not verifying

            
The payload of a JWT is base64url, not encryption. Anyone holding the token can read every claim in it, which is why you must never put a secret in one. Only the signature says whether the claims were tampered with, and checking it needs the key.

          

          

            
The alg: none attack

            
The header names the algorithm, and the header is attacker-controlled. A library that trusts it will happily accept {"alg":"none"} with an empty signature, letting anyone mint a token for any user. This tool flags it in red. Real servers should pin the expected algorithm rather than reading it from the token.

          

          

            
Expiry is the only revocation

            
JWTs are stateless, which means there is usually no way to revoke one before it expires. A token with no exp claim is valid forever. Short lifetimes plus a refresh token is the standard answer.

          

          

            
Why this one is local

            
The advice never to paste a production token into a website is correct, and awkward, because the well-known decoders are websites. This is the same tool without that problem: the token is split and verified with WebCrypto in your tab.

          

        

      


      

        

          
Questions people ask

        

          

            Is my token sent anywhere?
            
No. The token is decoded and verified in your browser using the built-in WebCrypto API. There is no server in this tool and no network request carries the token - open the Network tab in developer tools and you will see nothing.

          

          

            Can it verify RS256 or ES256 tokens?
            
Signature verification here covers HS256, HS384 and HS512, which use a shared secret. RS and ES algorithms are verified with a public key rather than a secret; the token is still fully decoded and all claims are checked, but the signature is not.

          

          

            Why does it say my token is expired when the app still works?
            
Expiry is compared against your device clock. If your clock is wrong, so is the answer. Servers also commonly allow a small amount of clock skew.

          

          

            Is a JWT encrypted?
            
No. A standard JWT is signed, not encrypted, and its payload is readable by anyone holding it. If you need the contents hidden, that is JWE, which is a different thing.

          

          

            What should I do if I pasted a real token into another site?
            
Treat it as compromised and invalidate the session. Anything with a long expiry and no revocation path is worth rotating.
