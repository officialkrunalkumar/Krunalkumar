What an operating system is deciding

Five families, one shell

Which process gets the CPU, which page gets evicted, what order the disk head serves requests in, where a process fits in memory, and whether a resource request is safe to grant. Each runs with the same controls — step, play, scrub, compare — so the differences you notice are differences between the algorithms, not between five unrelated toys.

Stepping backwards is the point

Every simulation runs to completion the moment you change an input, and the transport just indexes into the frames it produced. That is what makes stepping back free, which matters more than it sounds: you cannot study a preemption you only get to see once. The metrics shown are always the finished numbers, never a half-summed total.

The comparison table is the lesson

Every algorithm in the family is run against the input you typed, and the winning number is marked. It is easy to say “shortest remaining time gives the lowest average waiting time”; it is more convincing to change the arrival times and watch it stay true — and to find the inputs where a simpler policy ties it.

Conventions, stated rather than hidden

Round robin admits a new arrival before returning the process whose quantum just expired. SCAN runs to the end of the disk while LOOK turns at the last request. A lower priority number means higher priority. Textbooks differ on all three, and the numbers change when they do, so this page says which it uses rather than leaving you to guess why your homework disagrees.

Questions people ask

Which algorithms does it cover?
CPU scheduling: FCFS, SJF, shortest remaining time, round robin, and priority in both preemptive and non-preemptive forms. Page replacement: FIFO, LRU, optimal, clock and LFU. Disk scheduling: FCFS, SSTF, SCAN, C-SCAN, LOOK and C-LOOK. Memory allocation: first, best, worst and next fit. Plus the Banker algorithm for deadlock avoidance.
My textbook gets a different answer - who is wrong?
Probably neither. The usual culprits are the round robin ordering when a process arrives at the same instant a quantum expires, whether SCAN travels to the edge of the disk, and whether a low priority number means high priority. This page states each convention it uses, so you can see exactly where the two workings diverge.
Why does the safe sequence differ from mine?
A safe state usually has several safe sequences, and any one of them proves the state is safe. This runs the lowest-numbered process whose need fits at each round, so the result is reproducible; your book may pick a different one. If both sequences let every process finish, both are correct.
Does it show the Belady anomaly?
Yes - there is a preset for it. Load the Belady string under page replacement, run FIFO with three frames, then change it to four and watch the fault count go up rather than down. LRU and optimal cannot do that, and you can check both in the same two clicks.
Is anything uploaded?
No. Every simulation is arithmetic running in your tab. There is no server, no network request, and nothing is stored beyond the consent you gave once for the Labs section.
