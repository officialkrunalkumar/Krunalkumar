PDF tools that never see your document

Every free PDF site on the internet works by taking your file. People feed contracts, bank statements and passport scans into them daily. This one merges, splits, reorders, rotates and inspects without a single byte leaving the tab — because the PDF structure is parsed and rewritten here, by hand.

  • Merge, split, reorder, rotate
  • Reads xref streams and object streams
  • Fonts, attachments, JavaScript actions
  • Metadata stripper
  • Document never uploaded

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • No decryption of a password-protected file
  • No re-encoding of images, no OCR, no text editing

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

      How a PDF is actually put together
      
          
      None of this is guesswork or a library doing the work off-screen. The parser and the writer here are written from the specification, and these are the four things you have to get right before a page can be moved at all.
      
        
      
        
      
          
      
            
      Numbered objects and an index
      
            
      A PDF is a plain-text skeleton wrapped around binary blobs. The body is a list of numbered objects — 12 0 obj … endobj — and everything refers to everything else by number. At the end sits a cross-reference index giving the byte offset of each one, and after that the word startxref and the offset of the index itself. You read a PDF backwards: last line first, then the index, then the objects it names.
      
          
      
          
      
            
      The index has two shapes
      
            
      The original is a table of fixed twenty-byte records. PDF 1.5 added the xref stream: the same table, compressed, stored as an object with its own field widths and usually a PNG predictor on top. Every current producer writes the second kind, so a tool that only handles the first fails on most files it is given. This one reads both, and the hybrid files that carry one of each.
      
          
      
          
      
            
      Objects that are not in the file
      
            
      PDF 1.5 also lets a producer pack hundreds of small dictionaries into one compressed object stream, so those objects never appear as n 0 obj anywhere. The index says “object 12 is item 4 inside object 40”. Reaching them means implementing DEFLATE, which is why there is an inflater in this page and why it is checked against fixtures on every load.
      
          
      
          
      
            
      Pages inherit from their parents
      
            
      Pages hang in a tree, and /Resources, /MediaBox, /CropBox and /Rotate are inherited down it. A page can declare none of them and still be perfectly well defined. Move that page into a new document without pushing the inherited values down with it and you get a page with no size, no fonts and no rotation — which is the classic way a hand-rolled merge produces blank sheets.
      
          
      
        
      
      
      

      
      
        
      
          
      What the inspector reads, and why each one matters
      
        
      
        
      
          
      
            
      JavaScript and launch actions
      
            
      A PDF can run script when it opens, when a page is shown, or when a field changes. It can also ask the reader to launch a program, submit form data to a URL, or import a file from disk. Outside a real form none of that is normal, and all of it is the first stage of a malicious document. The report counts each kind and prints the first ninety characters of the script as text. It never executes any of it.
      
          
      
          
      
            
      Attachments
      
            
      A PDF can carry whole files inside it, extracted by a double click. The report names them and gives their size, and never opens one. Treat an attached file exactly the way you would treat the same file arriving on its own in an email — the PDF wrapper does nothing to make it safer, and does quite a lot to make it look harmless.
      
          
      
          
      
            
      Fonts, embedded and missing
      
            
      Each font is listed with its type, whether the outline is actually inside the file, and whether it is a subset — the ABCDEF+ prefix means only the glyphs the document uses were included. A font that is not embedded is substituted by whatever the reader happens to have, which is the usual reason a document reflows on somebody else’s machine and a signature block ends up on its own page.
      
          
      
          
      
            
      Metadata, in two places
      
            
      The /Info dictionary holds title, author, subject, keywords, creator, producer and both timestamps. Modern files often carry an XMP packet as well. Creator and Producer name the software and frequently its exact version, which is a fingerprint of your machine, and Author is often a login name nobody meant to publish. The stripper removes both.
      
          
      
          
      
            
      How many times it was saved
      
            
      A PDF can be edited by appending to it: each revision writes its own index pointing back at the previous one. Counting that chain tells you how many times the file has been saved since it was created. On a document somebody says they have not touched, that number is a real signal — and the earlier revisions are still in the bytes.
      
          
      
          
      
            
      Encryption, described not defeated
      
            
      If the file is encrypted the report names the handler, the algorithm and revision, the key length, and which permission bits are set. Those bits are advisory — they are enforced by the reader, not by cryptography, which is why every tool that ignores them can. Naming them is useful. Breaking them is not this tool’s job.
      
          
      
        
      
      
      

      
      
        
      
          
      What it will not do, said plainly
      
          
      A tool that fails quietly is worse than one that refuses. Each of these is a deliberate refusal rather than a gap I have not got to yet.
      
        
      
        
      
          
      
            
      It will not decrypt anything
      
            
      A password-protected file is reported and then refused. Its strings and streams are ciphertext keyed partly to the original file identifier, so copying them into a new document unchanged gives you something that opens and shows nothing at all. There is no cracking here and no “remove owner password” shortcut, for either kind of password.
      
          
      
          
      
            
      It will not touch your images
      
            
      No re-encoding, no downsampling, no compression setting. Image data and font programs are copied as raw bytes with their filters intact. The upside is that quality is exactly preserved. The downside, stated honestly, is that this is not a compressor: a merged file is usually a little larger than the parts that went into it.
      
          
      
          
      
            
      It will not read or edit the text
      
            
      No OCR, and no editing of page content. Text inside a PDF is a sequence of drawing operators against a font’s internal glyph numbering, and changing a word means re-laying out everything after it. That is a typesetting job, not a file-format one. This tool works at the level of whole pages.
      
          
      
          
      
            
      The output leaves four things behind
      
            
      Bookmarks, the AcroForm dictionary and any filled form data, document-level JavaScript, and the tagged structure tree screen readers use. All four index the whole original document, and a partial copy of an index is worse than none. Losing the document JavaScript is a feature; losing the tag tree is a genuine accessibility cost, and if your document is tagged you should keep the original.
      
          
      
          
      
            
      It rebuilds broken files rather than guessing
      
            
      If the cross-reference index does not lead anywhere usable, the whole file is scanned for objects and the index is rebuilt from what is really there — the same recovery a real reader does. The report says when that happened, because it means the file is damaged even if the pages come back looking fine.
      
          
      
          
      
            
      It refuses rather than half-writing
      
            
      If anything goes wrong while building the output, nothing is saved and the pane says why. Half a PDF is a file that opens, shows a blank page, and makes you think the original was the problem. A refusal you can read is a much better outcome than a document you find out about later.
      
          
      
        
      
      
      

      
      
        
      
          
      How I checked this, and what I did not
      
        
      
        
      
          
      
            
      The self-check in the toolbar
      
            
      Six assertions run at load and the count is shown next to the buttons. Three of them exist because of the inflater: it is written from RFC 1951 with nothing to compare against, and a wrong bit there produces plausible garbage rather than an error, so a dynamic-Huffman stream, a fixed-Huffman stream with back-references and a stored block are each decompressed to known text before you touch anything. The other three cover the number formatting the writer emits, the way a page range is parsed, and the fact that a cross-reference record is exactly twenty bytes — the other three places where an off-by-one would be silent rather than loud.
      
          
      
          
      
            
      Against real files, in both directions
      
            
      While building it I ran documents through it and back: a classic-table file, one with an xref stream and object streams, an encrypted one, a 200-page one, files with junk before the header, with a truncated trailer, with a /Length that lies, and with a page-tree loop. The outputs were checked by two independent PDF libraries for page count, page size, rotation, extracted text, surviving images and links, and the absence of stripped metadata.
      
          
      
          
      
            
      What is not covered
      
            
      I have not tested this against every producer in the world, and PDF is a format where the interesting files are the malformed ones. Encrypted files are refused rather than handled. Image codecs are never decoded. If your file is unusual and the tool gets it wrong, that is a bug I want to see rather than a limitation I would defend.
      
          
      
          
      
            
      Why there is no compression
      
            
      The output writes a plain cross-reference table and never produces a compressed stream. Reading DEFLATE and writing it are not the same difficulty, and a hand-rolled compressor is where quiet corruption lives. Twenty extra bytes per object is a price worth paying for an output that every reader since 1993 can open.

      Questions people ask
      
        
      
          
      
            Is my document uploaded?
            
      No. There is no server here to upload it to. The file is read with FileReader, parsed in this tab, and handed back as a blob URL. That matters more for PDFs than for almost anything else, because the documents people put into a free PDF site are contracts, bank statements, medical letters and passport scans.
      
          
      
          
      
            Can it open a password-protected PDF?
            
      No. If the trailer carries an /Encrypt dictionary then the strings and streams are ciphertext, and copying them into a new file unchanged would produce something that opens and then shows nothing. So it reports what the encryption is and refuses. Remove the protection in the application that made the file, then come back.
      
          
      
          
      
            Will merging change my images or fonts?
            
      No. Content streams, embedded font files and image data are copied byte for byte with their original filters intact. Nothing is decoded and re-encoded, which is why there is no quality setting anywhere on this page and why the pixels that come out are the pixels that went in.
      
          
      
          
      
            What does the output leave behind?
            
      Bookmarks, the AcroForm dictionary and any filled form data, document-level JavaScript, and the tagged-PDF structure tree that screen readers use. All four index the whole original document, and half a copy of an index is worse than none. If you need any of them preserved, this is the wrong tool, and I would rather say so here than have you find out afterwards.
      
          
      
          
      
            Why did it say the cross-reference index was rebuilt?
            
      Because the index inside the file did not lead anywhere usable, so the whole file was scanned for objects instead. That happens with a truncated download, a file something was still writing, or one edited by a program that got its offsets wrong. Rebuilding is what real readers do and the pages usually come back intact - but it is worth knowing the file is damaged.
      
          
      
          
      
            Does it make the file smaller?
            
      No, and a merged file is often a little larger than the parts it came from. Nothing is recompressed, and the output uses a plain cross-reference table rather than the compressed one modern producers write, which costs about twenty bytes per object. A tool that shrank your document would have to re-encode its images, and that is precisely what this one refuses to do.
