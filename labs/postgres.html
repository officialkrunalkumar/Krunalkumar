Online PostgreSQL compiler

This is the real PostgreSQL server — not a Postgres-compatible engine, not a translation layer — compiled to WebAssembly and running single-user inside your tab. The dialect, the data types, the error messages and the planner are all genuinely Postgres, which is what makes it worth 17 MB when SQLite is 700 KB.

  • The actual Postgres server
  • ~17 MB once, then cached
  • Window functions, CTEs, JSONB
  • Fresh database every run

Before you start

This playground runs entirely inside your browser. Please read what it can and cannot do, then choose whether to continue.

What is not supported

  • Installing libraries or packages of any kind
  • Network access from your program
  • Reading or writing files on your computer
  • Long-running, timing-sensitive or benchmark work
  • Anything beyond the standard library

What you get

  • Your code runs on your machine, in your RAM
  • Nothing is uploaded, logged or stored by us
  • No account, no queue, no execution limits
  • Works offline once the runtime is cached
  • Free, permanently

How to run PostgreSQL online

  1. Accept the short notice, then replace the starter script with your own SQL.
  2. The database is created fresh on every run, so keep your CREATE TABLE and INSERT statements in the script.
  3. Press Run, or Ctrl + Enter.
  4. The first run downloads the server (~17 MB) and takes a few seconds; after that a query runs in well under a second.
  5. Every statement returning rows is rendered as its own table.

What this PostgreSQL playground supports

Almost all of Postgres, because it is Postgres. The limits are the sandbox and the single-user, in-memory setup around it.

Works here

  • Window functions, recursive CTEs, LATERAL joins and subqueries
  • JSONB with ->, ->>, ? and the containment operators
  • Arrays, ENUM, SERIAL, NUMERIC, UUID, ranges and the full type system
  • generate_series, string functions, date arithmetic and intervals
  • Views, triggers, constraints, indexes and transactions

Does not work here

  • Extensions that are not bundled — there is no way to install one
  • Replication, multiple connections and anything about concurrency
  • Saving the database: it lives only for the duration of a run
  • COPY from a file on your computer
  • Meaningful performance work — a WASM build is not the place to tune a query plan

PostgreSQL queries to try

Each one is complete and was run against this exact build. Copy any of them straight over the editor.

Window functions

Rank within a group — the thing SQLite users most often miss.

CREATE TABLE emp (name TEXT, dept TEXT, salary NUMERIC);

INSERT INTO emp VALUES
  ('Asha','Engineering',92000), ('Ben','Engineering',78000),
  ('Chitra','Design',71000), ('Eli','Design',83000);

SELECT name, dept, salary,
       RANK()       OVER (PARTITION BY dept ORDER BY salary DESC) AS rank,
       ROUND(AVG(salary) OVER (PARTITION BY dept)) AS dept_avg
FROM emp
ORDER BY dept, rank;

JSONB

Postgres' JSON type, with operators SQLite simply does not have.

CREATE TABLE events (id SERIAL PRIMARY KEY, payload JSONB);

INSERT INTO events (payload) VALUES
  ('{"user":"asha","action":"login","tags":["web","in"]}'),
  ('{"user":"ben","action":"purchase","amount":250}');

SELECT payload->>'user' AS person,
       payload->>'action' AS action,
       payload->'tags' AS tags
FROM events
WHERE payload ? 'user';

Generate a series

generate_series is a Postgres staple for building test data.

SELECT d::date AS day,
       EXTRACT(DOW FROM d) AS day_of_week
FROM generate_series('2026-01-01'::date, '2026-01-07'::date, '1 day') AS d;

CTE with a recursive term

Recursive CTEs walk hierarchies — org charts, trees, graphs.

WITH RECURSIVE countdown(n) AS (
  SELECT 5
  UNION ALL
  SELECT n - 1 FROM countdown WHERE n > 1
)
SELECT n, REPEAT('*', n) AS bar FROM countdown;

Questions people ask

Is this really PostgreSQL, or something compatible?
It is genuinely PostgreSQL — the server source, compiled to WebAssembly by the PGlite project. That is why JSONB, window functions and Postgres' own error messages all behave exactly as they do on a real install.
How is this different from the SQL playground?
The other one runs SQLite, which is a different database with a different dialect. SQLite is 700 KB and starts instantly; Postgres is 17 MB and gives you the full feature set. Use SQLite to practise general SQL, and this when you specifically need Postgres behaviour.
Does my data persist?
No. A fresh in-memory database is created per run, which is why the starter script carries its own schema. Keep the CREATE and INSERT statements at the top.
Can I install extensions like PostGIS?
No. Only what is bundled is available, and there is no network to fetch anything from.
Is my SQL private?
Completely. The server runs in your browser's memory and is destroyed when the run ends. Nothing is transmitted.
