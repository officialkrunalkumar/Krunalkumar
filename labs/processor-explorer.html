Inside a processor

Scroll to fly inward. The chip package opens into the silicon die, the die into one core’s pipeline, the pipeline into an arithmetic unit, that into a single logic gate, and the gate into one transistor switching. Data pulses through every level, so you can see that a program is, in the end, charge moving through switches.

What you are looking at

Six levels, one continuous descent

Package → die → core → execution unit → logic gate → transistor. Each is drawn as its own scene and cross-fades into the next as you zoom, so the descent feels like flying in rather than flipping through slides. The hierarchy is the real one: that is genuinely how a processor is built, layer inside layer.

The data is the point

At every level something is moving — packets on the ring bus between cores and cache, instructions marching through fetch, decode and execute, carry bits rippling along an adder, electrons crossing a channel when the gate opens. The animation is there to show that computation is signals in motion, not a static diagram.

Why it ends at a transistor

Because that is where the abstraction bottoms out. A modern chip has tens of billions of them, and each one is just a switch. Everything above — the gate, the adder, the pipeline, the program — is built from switches turning on and off. Seeing the whole stack in one continuous zoom is the clearest way to feel that.

An illustration, not a photograph

The proportions and layout are stylised for legibility: a real die photo is a grey maze, and real feature sizes are far below what light can resolve. What is accurate here is the structure and the order — what contains what, and what flows where.

Questions people ask

Is this a real chip layout?
It is an accurate illustration of the hierarchy rather than a photograph of one specific processor. The containment and the data paths are real - package holds the die, the die holds cores and cache, a core holds a pipeline, and so on down to transistors - but the geometry is stylised so each level stays readable.
How do I move around?
Scroll to zoom in and out, use the + and - buttons or the depth slider, or click a level on the depth rail to jump straight there. Play/pause controls the data animation and reset returns you to the package view.
How is this different from the CPU simulator?
The CPU simulator runs code - you write assembly and step through it watching registers change. This one is the physical journey: what a processor is made of, from the outside in. One is about execution, the other about structure.
Does it need a powerful machine?
No. It is canvas 2D drawing, not 3D rendering, so it runs comfortably on any modern browser and respects your reduced-motion setting if you have one.
Is anything uploaded?
No. Every frame is drawn in your browser and there is no network request.
