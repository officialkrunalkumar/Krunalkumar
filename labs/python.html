Online Python compiler

This is genuine CPython — the same interpreter you would download from python.org — compiled to WebAssembly and running inside your browser tab. It is not a reimplementation or a subset. Nothing you type is uploaded. There is no server that compiles your code, no account to create and no execution quota, because the work happens on your own processor.

  • Real CPython 3
  • ~12 MB once, then cached
  • Full standard library
  • input() and stdin supported

Before you start

This playground runs entirely inside your browser. Please read what it can and cannot do, then choose whether to continue.

What is not supported

  • Installing libraries or packages of any kind
  • Network access from your program
  • Reading or writing files on your computer
  • Long-running, timing-sensitive or benchmark work
  • Anything beyond the standard library

What you get

  • Your code runs on your machine, in your RAM
  • Nothing is uploaded, logged or stored by us
  • No account, no queue, no execution limits
  • Works offline once the runtime is cached
  • Free, permanently

How to run Python online

  1. Accept the short notice explaining the limits, then start typing.
  2. Replace the starter program with your own Python.
  3. If your program calls input(), put each expected value on its own line in the Input (stdin) box before running.
  4. Press Run, or Ctrl + Enter.
  5. Output and full tracebacks appear in the terminal pane on the right.

What works in this Python playground

The interpreter is complete and the standard library is present. The gap is third-party packages, which would need pip and a network connection.

Works here

  • The whole language: comprehensions, decorators, generators, async/await, dataclasses, pattern matching
  • Standard library modules including json, re, math, itertools, collections, datetime, random, hashlib
  • Classes, inheritance, context managers and exceptions with real tracebacks
  • Recursion and arbitrary-precision integers

Does not work here

  • pip install — no package manager and no network to reach one
  • NumPy, pandas, requests, Django and every other third-party library
  • Opening files on your computer, or writing files that persist
  • Threads, subprocesses and os.system
  • GUI toolkits such as tkinter, and anything that opens a window

Python examples to try

Copy any of these into the editor. The first one needs a value in the Input panel.

Reading input

Put a number on the first line of the Input panel, then run.

n = int(input("How many terms? "))

a, b = 0, 1
for _ in range(n):
    print(a, end=" ")
    a, b = b, a + b
print()

Counting words

collections.Counter is part of the standard library, so it is available.

from collections import Counter

text = """the quick brown fox
jumps over the lazy dog
the fox sleeps"""

for word, n in Counter(text.split()).most_common(5):
    print(f"{n:>3}  {word}")

Classes and dataclasses

Modern Python features work exactly as they do locally.

from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

    def dist(self) -> float:
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3, 4)
print(p)
print(f"distance = {p.dist()}")

Seeing a traceback

Errors print the real CPython traceback, not a simplified message.

def divide(a, b):
    return a / b

print(divide(10, 2))
print(divide(1, 0))

Questions people ask

Is this real Python or a simulation?
It is real CPython, compiled to WebAssembly through the Pyodide project. The interpreter is the genuine article, which is why tracebacks and edge-case behaviour match what you get locally.
Can I use pip install, NumPy or pandas?
No. This playground is deliberately limited to the standard library. Installing packages requires a package index and network access, and neither is available by design.
How do I give input to input()?
Type it into the Input panel below the output, one value per line, before pressing Run. Each call to input() consumes the next line.
Why is the first run slower?
CPython plus the standard library is roughly 12 MB, downloaded once. Your browser caches it, so subsequent runs start almost instantly — and it then works offline.
Is my Python code private?
Completely. The interpreter runs in your browser using your own memory and CPU. Your code is never transmitted, stored or seen by anyone.
What if my program never finishes?
It runs in a Worker separate from the page, so your tab stays usable. A warning with a Cancel button appears after a few seconds, and the run is killed at sixty seconds.

Something not working?
