Regex tester and ReDoS checker

Ordinary testers show you matches. This also runs a ReDoS check, because a regular expression is one of the few places where harmless-looking code can be brought down by a 40-character input — and the usual way people find out is in production.

  • Live matching with capture groups
  • Named groups and replacement
  • Automatic catastrophic-backtracking test
  • 14 security-relevant patterns built in
  • Nothing uploaded

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Uses the JavaScript regex engine, not PCRE or RE2
  • The ReDoS check is empirical, not a proof

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

Regex as an attack surface

        

        

          

            
Catastrophic backtracking

            
Patterns with a repeat inside a repeat — (a+)+ — or with overlapping alternations force the engine to try every possible way of splitting the input before giving up. The cost doubles with each added character, so a 40-character string can take longer than the age of the universe.

          

          

            
Why that is a denial of service

            
On a single-threaded runtime, one request carrying a crafted string stalls the whole process. It needs no privileges, no account and no unusual traffic volume. Cloudflare and Stack Overflow have both had public outages from exactly this.

          

          

            
How the check works here

            
Rather than analysing the pattern theoretically, it runs it against deliberately pathological inputs of increasing length and times each one. If the runtime explodes, you see it explode — in your tab, where it costs nothing.

          

          

            
The fixes

            
Remove the nesting, since (a+)+ almost always means (a+). Make alternations mutually exclusive. Bound repetition with {1,64}. Anchor the pattern so failure is decided early. For input you do not control, use a linear-time engine such as RE2.

          

        

      


      

        

          
Questions people ask

        

          

            What is ReDoS?
            
Regular expression denial of service: a pattern whose matching time grows exponentially with input length, so a short crafted string can hang the process that evaluates it.

          

          

            How does the ReDoS check work?
            
It runs your pattern against deliberately pathological strings of increasing length and measures the time. If it crosses a threshold, the growth is exponential and the pattern is flagged. It is an empirical test, not a formal proof, so a clean result means "no blow-up observed" rather than "provably safe".

          

          

            Which regex flavour is this?
            
JavaScript, since it runs in your browser. Most of what you write will behave the same in PCRE, but lookbehind support, named group syntax and some Unicode property escapes differ.

          

          

            Is my pattern or test data sent anywhere?
            
No. Both stay in your browser.

          

          

            Why does my pattern with a huge match count feel slow?
            
The tool caps display at 60 matches and stops iterating at 5000 to keep the page responsive. A pattern that matches an empty string can also loop, which is guarded against.
