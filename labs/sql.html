Online SQL compiler

A genuine SQLite database engine, running in your browser and held entirely in memory. Create tables, insert data and query it — results come back as a formatted table. Perfect for practising SQL without installing anything. Nothing you type is uploaded. There is no server that compiles your code, no account to create and no execution quota, because the work happens on your own processor.

  • Real SQLite engine
  • ~350 KB once, then cached
  • Results as a formatted table
  • Fresh database every run

Before you start

This playground runs entirely inside your browser. Please read what it can and cannot do, then choose whether to continue.

  • Long-running, timing-sensitive or benchmark work
  • Anything beyond the standard library

What you get

  • Your code runs on your machine, in your RAM

How to practise SQL online

  1. Accept the notice, then look at the starter script — it creates a small employee table and queries it.
  2. Because the database is created fresh on every run, your CREATE TABLE and INSERT statements need to stay in the script.
  3. Add your own queries at the bottom, or replace the whole thing.
  4. Press Run, or Ctrl + Enter.
  5. Every statement that returns rows is rendered as its own table on the right.

What this SQL playground supports

The engine is SQLite, so SQLite's dialect is what applies. That is close to standard SQL for everyday work, but it is not MySQL, PostgreSQL or SQL Server — worth knowing if you are preparing for something specific.

Works here

  • CREATE TABLE, INSERT, UPDATE, DELETE, DROP
  • SELECT with JOIN, GROUP BY, HAVING, ORDER BY and subqueries
  • Aggregates, CASE, common table expressions and window functions
  • Indexes, views, triggers and transactions
  • Constraints: primary keys, foreign keys, NOT NULL, UNIQUE

Does not work here

  • MySQL, PostgreSQL and T-SQL specific syntax and functions
  • Stored procedures — SQLite has no procedural language
  • RIGHT JOIN and FULL OUTER JOIN on older engine builds
  • Saving the database: it exists only for the duration of a single run
  • Importing a .sql dump or a .db file from your computer

SQL queries to try

Each one is complete — schema included — so you can copy it straight over the editor and press Run.

Join two tables

A second table, and an inner join across it.

CREATE TABLE dept (name TEXT PRIMARY KEY, city TEXT NOT NULL);
CREATE TABLE emp  (name TEXT, dept TEXT, salary INTEGER);

INSERT INTO dept VALUES
  ("Engineering", "Pune"), ("Design", "Ahmedabad"), ("Sales", "Mumbai");

INSERT INTO emp VALUES
  ("Asha", "Engineering", 92000), ("Ben", "Engineering", 78000),
  ("Chitra", "Design", 71000), ("Dev", "Sales", 64000);

SELECT e.name, e.dept, d.city
FROM emp e
JOIN dept d ON d.name = e.dept
ORDER BY d.city;

Window function

Rank people by salary within their own department.

CREATE TABLE emp (name TEXT, dept TEXT, salary INTEGER);

INSERT INTO emp VALUES
  ("Asha", "Engineering", 92000), ("Ben", "Engineering", 78000),
  ("Chitra", "Design", 71000), ("Dev", "Sales", 64000),
  ("Eli", "Design", 83000);

SELECT name, dept, salary,
       RANK() OVER (PARTITION BY dept ORDER BY salary DESC) AS rank_in_dept
FROM emp
ORDER BY dept, rank_in_dept;

Common table expression

A CTE to filter first, then aggregate over the result.

CREATE TABLE emp (name TEXT, dept TEXT, salary INTEGER);

INSERT INTO emp VALUES
  ("Asha", "Engineering", 92000), ("Ben", "Engineering", 78000),
  ("Chitra", "Design", 71000), ("Dev", "Sales", 64000),
  ("Eli", "Design", 83000);

WITH well_paid AS (
  SELECT * FROM emp WHERE salary > 70000
)
SELECT dept, COUNT(*) AS n, MAX(salary) AS top
FROM well_paid
GROUP BY dept
ORDER BY top DESC;

Conditional aggregation

CASE inside an aggregate, to count a subset per group.

CREATE TABLE emp (name TEXT, dept TEXT, salary INTEGER);

INSERT INTO emp VALUES
  ("Asha", "Engineering", 92000), ("Ben", "Engineering", 78000),
  ("Chitra", "Design", 71000), ("Dev", "Sales", 64000),
  ("Eli", "Design", 83000);

SELECT dept,
       COUNT(*) AS total,
       SUM(CASE WHEN salary >= 80000 THEN 1 ELSE 0 END) AS senior
FROM emp
GROUP BY dept;

Questions people ask

Which SQL dialect is this?
SQLite. It covers standard SQL closely for everyday querying, including window functions and CTEs, but MySQL- or PostgreSQL-specific syntax will not work.
Does my data persist between runs?
No. A fresh in-memory database is created for every run, which is why the starter script includes its own CREATE TABLE and INSERT statements. Keep them at the top.
Can I upload a .db or .sql file?
Not currently. Everything has to be written as statements in the editor.
Is this good for practising SQL interview questions?
Yes, particularly for joins, grouping, subqueries and window functions. Just be aware that if the interview targets MySQL or PostgreSQL specifically, a few functions will differ.
Is my query data private?
Entirely. The database lives in your browser's memory and is destroyed when the run ends. Nothing is sent anywhere.
