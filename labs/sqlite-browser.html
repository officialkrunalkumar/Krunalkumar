SQLite database browser

Chrome history, Firefox bookmarks, WhatsApp backups, iOS app data — they are all SQLite. Being able to open one and read it without handing the file to a website is the whole point, and it runs on the same real SQLite engine as the SQL lab.

  • Every table, view, index and trigger
  • Paginated row browsing
  • Free-form SQL queries
  • Recognises forensic databases
  • Decodes WebKit & Firefox timestamps

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Large files are capped so the page stays responsive
  • No lookups against any external database

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

So much is SQLite

            
Browsers, phones and desktop apps store their data in SQLite because it is a single file with no server. Chrome’s History and Cookies, Firefox’s places.sqlite, Signal, WhatsApp’s msgstore, and most iOS app data are all SQLite databases — which is why a forensic examiner opens more of them than anything else.

          

          

            
The timestamp trap

            
Each of those uses a different epoch. Chrome stores time as microseconds since 1601, Firefox as microseconds since 1970, others as seconds since 1970. Read one with the wrong epoch and an event lands centuries away. When this tool recognises a known database it decodes the timestamps for you.

          

          

            
Browse or query

            
Click a table to page through its rows with column types, or write your own SQL in the box. It is your file and the database is in memory, so a write statement only touches the copy in the tab — the original file on disk is never modified.

          

          

            
Deleted data

            
The header reports the free-page count, a hint at how much deleted content might be recoverable. Full carving of deleted rows is a deeper job, but knowing there is free space is where it starts.

          

        

      


      

        

          
Questions people ask

        

          

            Is my database uploaded?
            
No. It is loaded into sql.js - a real SQLite engine compiled to WebAssembly - entirely in your browser. There is no server and no network request.

          

          

            Can I open a Chrome or WhatsApp database?
            
Yes. Point it at the file and it will recognise common forensic databases from their schema, offer a useful preset query, and decode their timestamps. WhatsApp message databases are often encrypted (.crypt14), which must be decrypted first with the key - this opens the decrypted .db.

          

          

            Will it change my file?
            
No. The database is loaded into memory; any query, even a write, affects only that in-memory copy. The file on disk is untouched.

          

          

            Why does a query fail with "no such table"?
            
Table names are case-sensitive and some contain characters that need quoting. Use the table dropdown to see exact names, or query sqlite_master to list them.

          

          

            What is the size limit?
            
Up to 256 MB. Beyond that the browser tab struggles to hold the whole database in memory.
