Unicode inspector

A string is a sequence of code points. What you see is a picture of it. Almost every Unicode bug that becomes a security bug lives in the gap between the two — a username with an invisible character in it, a domain spelled in Cyrillic, a line of source that reads one way and compiles the other. Paste something in and the gap becomes visible.

  • Every code point, named and decoded
  • Invisible and bidi characters shown in place
  • Homoglyph and domain spoof analysis
  • NFC, NFD, NFKC and NFKD side by side
  • Trojan Source detection
  • Nothing uploaded

Before you start

This tool runs entirely inside your browser. Nothing you paste or drop here is uploaded, logged or stored — which for security work is the whole point, not a footnote.

What it does not do

  • No uploads — there is no server to upload to
  • No account, no history, nothing saved
  • Character names are partial; category and script are exact
  • The confusable table is curated, not the full UTS 39 set

Why that matters here

  • Evidence files stay on your machine
  • A token or key you paste is never transmitted
  • Nothing you paste ever appears in your Network tab
  • Works with no internet once the page is cached
  • Free, permanently

Where the gap opens up

        

        

          

            
Characters that paint nothing

            
ZERO WIDTH SPACE, the byte order mark, the soft hyphen and the two joiners occupy a position and draw nothing. They survive copy and paste, they count towards length limits, and a filter that blocks admin does not block ad plus a zero-width space plus min. Tag characters go further: U+E0000 to U+E007F are an invisible copy of ASCII, so an entire sentence can travel inside a string that renders as three words.

          

          

            
Homoglyphs and the address bar

            
Cyrillic а and Latin a are different characters that most fonts draw identically. A domain using one for the other is a different domain that looks like yours. The skeleton in the report replaces every lookalike with the plain character it imitates, so two names a person cannot tell apart collapse to the same string — which is the only comparison worth running before you register or trust a name.

          

          

            
Bidi overrides reorder the display

            
RIGHT-TO-LEFT OVERRIDE and the isolate characters change the order text is drawn in without changing the order it is stored in. An attachment stored as invoice…gnp.exe displays as invoice.png. Source code stored one way compiles differently from the way it reviews. In both cases the display is the lie and the bytes are the truth.

          

          

            
Normalisation and uniqueness

            
NFC composes accents onto their letters. NFKC goes further and folds compatibility variants, so fullwidth ａｄｍｉｎ, the fi ligature and the mathematical alphabets all collapse to plain ASCII. If a signup form stores what was typed and checks uniqueness against what was stored, two visually identical usernames become two accounts. Normalise, then check, then store both.

          

          

            
Three ways to count one string

            
A family emoji is one thing to a person, seven code points to a string, and twenty-five bytes to a file. A validator that trims at twenty characters, a database column that counts bytes and a UI that counts what the user sees will disagree, and the disagreement shows up as half an emoji, a mojibake tail, or a string a decoder rejects.

          

          

            
What to actually do

            
Decide what your inputs are allowed to contain and enforce it at the edge: usernames and identifiers rarely need formatting characters at all. Normalise to NFKC before any uniqueness or equality check. Reject bidi controls in source at commit time. And when something looks wrong but reads fine, paste it here before you spend an afternoon on it.

          

        

      


      

        

          
Trojan Source, in one snippet

          
The example below is the shape from the 2021 disclosure. Load it into the tool with the examples menu to see it with the real characters in place.

        

        
This is what a reviewer sees on screen:

        
var accessLevel = "user";
if (accessLevel != "user") {   // Check if admin
  grantAdminRights();
}

        
And this is what the file stores. Two bidi characters have been written
          out as red markers so this page stays readable; in the real file they
          are invisible and occupy no width at all.

        
var accessLevel = "user";
if (accessLevel != "userRLO LRI// Check if adminPDI LRI") {
  grantAdminRights();
}

        
The comment text is inside the string literal. The comparison therefore
          can never be true, the branch always runs, and every reviewer who read
          the first version approved the second. Nothing about the code is
          unusual; only the direction it is painted in changed.

        
    
          
  1. Reject bidi controls in source at commit time, in a hook or a CI step, unless a file genuinely needs them.
    2. 
          
  2. Turn on the compiler warning where there is one — rustc, gcc and clang all added one after the disclosure.
    3. 
          
  3. Make the code viewer show them. GitHub warns about bidi characters in diffs, and most editors can render them as visible marks.
    4. 
          
  4. For a first pass, grep is enough: U+202A to U+202E, U+2066 to U+2069, U+200E, U+200F and U+061C.
    5. 
        

        
The same trick works outside source code. An email display name, a
          commit message, a filename in an archive and a support ticket all render
          through the same algorithm. If you take phishing artefacts apart
          regularly, the phishing dissector,
          the URL inspector and the
          email header analyzer handle the parts
          of that job that are not about characters.

      


      

        

          
Questions people ask

        

          

            Is my text sent anywhere?
            
No. Every code point is examined in your browser, and the character data comes from the browser's own Unicode tables rather than a lookup service. There is no server behind this page and no network request when you press Inspect.

          

          

            What is a zero-width character?
            
A code point that occupies a position in a string and paints nothing. Zero width space, the byte order mark, the soft hyphen and the two joiners are the common ones. They survive copy and paste, they count towards a length limit, and two strings that differ only by one of them are different strings to every computer and the same string to every person.

          

          

            What is Trojan Source?
            
A 2021 result showing that bidirectional formatting characters let source code display in one order and compile in another. The reviewer approves what the screen shows and the compiler reads what the file stores. Every language with comments and string literals is affected, which makes it a review and CI problem rather than a bug in any one language.

          

          

            Why do two identical-looking usernames register as separate accounts?
            
Because the uniqueness check compared the raw strings. Normalise to NFKC first and compare the normalised values, which folds fullwidth letters, ligatures and the mathematical alphabets down to plain ASCII. Cross-script lookalikes such as Cyrillic a survive NFKC untouched, so compare confusable skeletons as well if impersonation is part of your threat model.

          

          

            Why does a character sometimes have no name here?
            
Because the full Unicode character database is megabytes and this page downloads nothing. Names are exact for ASCII, controls, formatting characters, bidi, tags, variation selectors and spaces, algorithmic for CJK, Hangul and private use, and absent for everything else. Category and script always come from the browser's own Unicode tables, so those two columns are exact for every character.

          

          

            How is a grapheme cluster different from a character?
            
A grapheme cluster is what a person would call one character. A family emoji is one cluster, seven code points and twenty-five UTF-8 bytes. Truncating by code points or by bytes can cut a cluster in half, which is how a length limit produces half an emoji and how a substring produces a string no decoder will accept.
