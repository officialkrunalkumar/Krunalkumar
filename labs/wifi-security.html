Wi-Fi security, from WEP to WPA3

Almost everything written about wireless security is either a list of router settings that change nothing, or a warning about public wifi that stopped being true around the time HTTPS became universal. This lab does the other thing: it draws the mechanism. Walk the five generations, step the WPA2 four-way handshake with every input marked public or secret, put the WPA3 exchange next to it, and see exactly why one of them can be guessed at offline and the other cannot. Explanation only — there is no capture step and no attack here.

The part that is worth understanding

Five of the six inputs travel in the clear

The WPA2 session key comes out of a pseudo-random function fed six things: the PMK, a fixed string from the standard, both MAC addresses and both nonces. The string is published. The MAC addresses are in every frame header. Both nonces are sent unencrypted during the handshake. The only input a listener does not have is the PMK — and the PMK is nothing but your passphrase and your network name. That is why the passphrase carries the entire network, and why “use a long random one” is a specific technical requirement rather than general advice.

Offline versus live is the whole difference

A captured WPA2 handshake contains a MIC that any candidate passphrase can be tested against. The testing happens on the attacker’s own hardware, at their own pace, with nothing sent back to the network — so there is nothing to rate-limit, nothing to lock out and nothing to log. SAE removes that. The password only enters the exchange blinded by random values that are never transmitted, so every guess has to be made live against the access point, which can slow it down, refuse it and record it. Same password, wildly different economics.

Forward secrecy is the quiet upgrade

Under WPA2-PSK the session key derives from the passphrase and two public nonces, so anyone who records encrypted traffic today and learns the passphrase in five years can decrypt what they recorded. SAE derives the session key from random values chosen fresh for each exchange and then discarded, so learning the password afterwards buys nothing against anything already recorded. It is the least advertised part of WPA3 and arguably the most valuable.

Most “hardening” is not security

A hidden SSID is still broadcast by every client that knows it. A MAC address is in the clear in every frame header, on every network, always, and it is a software setting on essentially every device. Both are settings that make a network list look tidier and change nothing an attacker has to do. What genuinely helps is short and dull: a long random passphrase, WPA3 with transition mode off, protected management frames on, WPS off, firmware updated, and guests on a properly isolated network.

Where this stops

What the page can show you, and what it deliberately does not.

It is an explanation, not a workshop

There is no capture step here, no cracking, nothing about knocking a device off a network, and no tool named for any of it. The mechanism and the defence are the content. If you want to know why a handshake is worth protecting, the derivation panel answers that far better than a command line would; if you want to run an attack, this is the wrong page and I am not going to write the right one.

The cryptography is drawn, not computed

This page performs no cryptography. The hex strings in the handshake family are a deterministic placeholder, present so that changing the network name visibly changes what depends on it — which is a real property, and the reason a precomputed table only ever helps against one SSID. Every panel that shows one says what it is. The structure, the key sizes and the role of each derived key are the genuine ones.

It cannot see your network

A web page has no access to a wireless adapter, so nothing here can tell you what your own network is running. Your router’s wireless settings page can, in one line. If it says WEP or WPA, that is worth acting on today; if it says WPA2, the passphrase is the thing to look at; if it offers WPA3, take it and check what stops working before you turn transition mode off.

Signals, not proof

The evil-twin family lists tells, and a tell is not evidence. Two access points with the same name is completely normal in any building large enough to need two. A portal appearing is normal. What is not normal is a certificate warning, a network that has lost its lock icon, or a sign-in page asking for a password that unlocks something other than the wifi — and those are the three worth acting on.

Questions people ask

Does this tool test my own wireless network?
No. It cannot see your network, your adapter or any network at all - a web page has no access to the radio. This is an explanation of how the protocols work, drawn so you can step through them. To check your own network, open your router's wireless settings and read what the security mode says.
Is WPA2 still safe to use?
With a long random passphrase, yes, and AES-CCMP itself has no practical break. But the four-way handshake gives anyone who observes it an offline target: they can test passphrase guesses at their own pace with nothing further sent to the network. That makes the passphrase the entire defence, so it has to be worth something. WPA3 removes the target rather than relying on the passphrase to survive it.
Why can a WPA3 handshake not be cracked offline?
Because the password only enters the exchange blinded by random values that are never transmitted. A listener ends up with two scalars, two curve elements and two confirm hashes, and testing a single password guess against any of it would mean solving a discrete logarithm. So each guess has to be tried live against the access point, one at a time, where it can be rate-limited, refused and logged.
Does hiding my network name make it harder to find?
No. The beacon stops carrying the name, but every association and every probe from every client that knows the network still carries it in the clear. It is hidden from someone scrolling a list of networks and from nobody else. It is also slightly worse than doing nothing, because devices configured for a hidden network go looking for it by name wherever they are.
Do I actually need a VPN on public wifi?
Usually not for the reason it is sold. HTTPS already protects the contents, the integrity and the identity of nearly everything you do, and it closed the classic public-wifi scenario years ago. What still leaks is which hosts you connect to, through DNS, the TLS SNI field and the destination addresses. If hiding that from the local network is a specific concern of yours, a VPN genuinely helps - but it moves that trust to the provider rather than removing it, and it does nothing about tracking, phishing or malware.
Are the keys and nonces on this page real?
No, and the page says so on screen where they appear. It performs no cryptography. The hex strings are a deterministic placeholder that exists so that changing the network name visibly changes what depends on it, which is a real property worth seeing. The structure of the derivation, the sizes and the roles of each key are the real ones.
